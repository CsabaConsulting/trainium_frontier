## Resolution of the r2 HOLD findings

1. **TMPDIR locality:** r3 adds an exclusive, no-follow scratch-root and `tmp/` creation step (after a future one-attempt marker), followed by an in-process G2-launcher guard. That guard requires the exact empty `TMPDIR` on the same filesystem, verifies owner/mode and current free bytes/inodes, resets and checks `tempfile.gettempdir()`, then pins `tempfile.tempdir` before invoking the unchanged G2 launcher through `runpy`. Missing or symlinked `tmp/` fails before `mkdtemp`; a candidate fallback is not accepted. Partial scratch is preserved on failure. The projection is intentionally unbound, so this remains an offline plan.
2. **Request pins:** the previously accepted zero inode floor and forged `.git` pointer SHA/mode and linked-gitdir mode are now rejected by `build_plan()`. The observed host identities are still historical snapshots; a future enabled request must establish fresh checkout, linked-Gitdir and source identity in its actual run session.
3. **Receipt consistency:** the validator now rejects divergent rank plan summaries, physically impossible touched-row counts (outside 1–524,288), and injected table-name fields. The supplied G2 tool emits only an ordered eight-record RMS trace, **not table identities**. Accordingly, even a structurally clean aggregate returns `numeric_gate: HOLD` and `per_table_attribution: HOLD_INDEPENDENT_RAW_PROOF_REQUIRED`; the draft cannot manufacture a per-table numeric PASS.
