## Blocking findings

1. **`TMPDIR` locality is not established before the planned child.** The runbook requires scratch/TMPDIR absent at preflight, and `build_plan()` sets `TMPDIR=<new scratch>/tmp` but includes no creation/identity check for that `tmp` directory. `contained.py launch` creates `<scratch>/process` and its parents, not `<scratch>/tmp`; the pinned G2 tool calls `tempfile.mkdtemp(prefix="g2-")` without an explicit `dir`. When `TMPDIR` does not exist, Python silently falls back to another writable temp filesystem (the independent local reproduction chose `/var/tmp`). The planned workdir/checkpoint could therefore land outside the projected ext4 scratch root before the result validator rejects the appended path. A separate enabled request must exclusively create and recheck the exact scratch and `tmp` identities, fail if the selected temp root differs, and include that operation in its reviewed one-attempt sequence.
2. **`build_plan()` does not authenticate every claimed request pin.** The independent mutation test changed `minimum_fresh_root_free_inodes` from 10,000 to zero, forged `host.git_pointer_sha256`, and changed `host.linked_gitdir_mode` from `0775` to `0777`; `build_plan()` still returned a normal disabled plan. Its command uses hardcoded paths, but the package calls these fields source/host/capacity bindings. Either validate all such fields against immutable expected values or clearly remove/defer them and bind the exact values in the separately reviewed enabled request. Do not treat this draft validator as a full preflight check.
3. **The G2 result validator can accept internally inconsistent numeric evidence.** It accepts a rank whose `plan_summary` differs from the other three despite the same asserted plan digest; it accepts `rows_touched=524289` for a table with only 524,288 rows. The pinned G2 tool emits eight RMS checks with step and size but **no table identity**; the validator only checks four step-1 and four step-2 records, so it cannot establish its stated “eight per-table update checks” property. An independent test that names all eight records as the same table still passes because the extra identity is ignored. The later result gate must add a reviewed per-table identity/index proof (which may require a separately reviewed G2-tool change), enforce physical row bounds and coherent ownership-plan evidence, and rehash the raw four-rank/checkpoint/step/containment artifacts rather than trusting this aggregate validator alone.

The independent negative reproducer is `research/v2/verification/test_20260925_a2_g2_disabled_independent_negatives.py`. It performs no host contact or model execution. Both `python -B -m unittest` and `python -OB -m unittest` passed the eight supplied plus five independent tests. These are *successful reproductions of acceptance defects*, not gate passes.
