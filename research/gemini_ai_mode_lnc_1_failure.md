# Q: Trainium Neural compiler LNC=1 crashes / hangs, LNC=2 works. What is the difference and what could eb the causes?

A: The behavior you are seeing is directly tied to how AWS Neuron abstracts physical hardware on Trainium2 (trn2) and Trainium3 (trn3) architectures. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/release-notes/components/compiler.html), [2] (https://naddod.medium.com/amazon-3nm-ai-chip-trainium3-deep-dive-93f5ea8141a2)

# The Core Difference: LNC=1 vs. LNC=2

The **Logical NeuronCore Configuration (LNC)** dictates how physical compute units are exposed to your ML application: [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-features/logical-neuroncore-config.html)
* **LNC=2 (Default)**: The compiler pairs two physical NeuronCores together into a single "Logical Core". They act as a coordinated unit, seamlessly sharing High-Bandwidth Memory (HBM) and compute structures. Because this is the native optimization path for modern Trainium chips, the compiler graph optimizer heavily prioritizes this layout. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/neuron-runtime/explore/device-memory.html), [2] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/nki_faq.html), [3] (https://awsdocs-neuron.readthedocs-hosted.com/en/v2.32.0/release-notes/components/compiler.html), [4] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-features/logical-neuroncore-config.html), [5] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/release-notes/components/compiler.html)
* **LNC=1**: Every single physical core is treated as an individual, decoupled logical core. While this doubles the total number of visible workers to your application, it completely shifts how the hardware manages memory boundaries and internal instruction scheduling. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-features/logical-neuroncore-config.html)

# Potential Causes for LNC=1 Crashes and Hangs

If your workload compiles and runs fine under `LNC=2` but crashes or freezes under `LNC=1`, it usually points to one of the following underlying issues:

1. **Mismatched Environment vs. Graph Compilation**
The AWS Neuron SDK **does not support** setting a compiler LNC flag that differs from your active runtime environment variable. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/v2.27.0/about-neuron/arch/neuron-features/logical-neuroncore-config.html)
   * **The Cause**: If you compiled your model (generating a `.neff` file) using the default `LNC=2` pipeline, but your environment variable `NEURON_LOGICAL_NC_CONFIG=1` forces a runtime execution layout of `LNC=1`, the memory addresses and instruction structures will warp. This mismatch frequently leads to immediate **bootstrapping hangs or segment faults** during initialization.
   * **The Fix**: Ensure that if you set `NEURON_LOGICAL_NC_CONFIG=1` at runtime, you also explicitly pass `-lnc 1` or `--logical-nc-config 1` during the `neuronx-cc compile` phase. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/compiler/error-codes/EARG001.html), [2] (https://awsdocs-neuron.readthedocs-hosted.com/en/v2.27.0/about-neuron/arch/neuron-features/logical-neuroncore-config.html), [3] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/release-notes/components/runtime.html), [4] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/release-notes/components/compiler.html)
2. **Noisy Neighbors and Sudden Device OOM**
When utilizing `LNC=1` on architectures like Trainium2, **two vertically neighboring cores end up sharing the same physical HBM bank**. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/neuron-runtime/explore/device-memory.html)
   * **The Cause**: Under `LNC=2`, memory allocation is unified and conflict-free. Under `LNC=1`, however, your code is subject to a "noisy neighbor" vulnerability. If both cores try to burst-allocate activation tensors or intermediate weights simultaneously, the HBM can unexpectedly exhaust its threshold. Instead of throwing a clean `Out of Memory` (OOM) error, the compiler or driver layer can lock up or terminate with a rough exit code. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/get-started/about/lnc.html), [2] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/about-neuron/arch/neuron-features/logical-neuroncore-config.html), [3] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/neuron-runtime/explore/device-memory.html), [4] (https://awsdocs-neuron.readthedocs-hosted.com/en/v2.28.0/compiler/error-codes/index.html), [5] (https://github.com/aws-neuron/aws-neuron-sdk/issues/1070)
3. **Undefined Dynamic Control Flow in NKI Kernels**
If your model relies on custom Triton or Neuron Kernel Interface (NKI) operators, the behavior differs fundamentally between core states. [1] (https://aws.amazon.com/blogs/migration-and-modernization/stop-hand-porting-kernels-migrate-pytorch-and-triton-kernels-to-aws-trainium-with-an-aws-transform-custom-agent/), [2] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/get-started/about/lnc.html)
   * **The Cause**: The Neuron SDK assumes that when splitting a graph down to bare cores, the base instruction flow remains symmetric. If your NKI kernel relies on dynamic control loops (`if/else` structures mapping to explicit `program_id` variations) that function natively across paired cores, dropping down to individual, unlinked cores (`LNC=1`) breaks that control logic. This leads to an unhandled exception or a perpetual synchronization loop (hang). [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/v2.32.0/release-notes/components/compiler.html), [2] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/get-started/about/lnc.html), [3] (https://awsdocs-neuron.readthedocs-hosted.com/en/latest/frameworks/jax/setup/jax-neuronx-known-issues.html)
4. **Compiler Linker Defect (Older SDK Versions)**
There are documented edge cases where the Neuron Graph Compiler (neuronx-cc) hits a snag with layout patterns under non-default constraints. [1] (https://awsdocs-neuron.readthedocs-hosted.com/)
   * **The Cause**: Early patch iterations of the trn2 compiler stack carried a known bug causing a linker failure and instruction post-scheduling freezes specifically for `LNC=1` layout patterns. [1] (https://awsdocs-neuron.readthedocs-hosted.com/en/v2.32.0/release-notes/components/compiler.html)
   * **The Fix**: Check your current AWS Neuron SDK release version. Upgrading to **Neuron 2.32.0 or newer** explicitly patches several `LNC=1` linker failures and improves instruction scheduling logic. [1] (https://awsdocs-neuron.readthedocs-hosted.com/), [2] (https://awsdocs-neuron.readthedocs-hosted.com/en/v2.32.0/release-notes/components/compiler.html)
