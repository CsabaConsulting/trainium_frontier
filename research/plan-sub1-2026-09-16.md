# Next-experiment plan for sub-1.0 bpb (2026-09-16)

Budget: each full run costs one 1800 s Trainium2 slot. Rule for every item:
**beat 1.004355 same-definition, in-budget, or stop.** Smoke (300-step) first
where noted; promote only on smoke wins.

## P0 — measurement hygiene (no training cost, unblocks everything)

1. **Reconcile the three eval defs.** Same checkpoint, three defs
   (in-process, sidecar, public script). Record tokens/shards per def.
   Relabel the leaderboard of past runs; retire any number whose def is
   unknown.

## Seed discipline (no seed hunt — dropped 2026-09-16)

A public-best seed hunt is selection bias: best-of-N on the visible eval
overstates the true gain, and expected transfer to the pinned private shard is
~zero. Worse, locking a "lucky" seed early distorts every later comparison.
Instead: **fix seed 42 as the control seed for all comparisons**, and only at
the very end re-verify the final config on 2–3 seeds, judging by the average
across eval defs, never the public-best outlier. Use the known spread (~0.006)
as a significance bar: future improvements must clear ~0.003 to count as
signal, not noise.

## P1 — throughput → steps (engineering, then 1 validation slot)

2. **NKI attention-forward port.** Port the fused attention forward from the
   neighboring NKI samples; measure steps/s delta at 300-step smoke.
   Promote to a full-budget run only if ≥ +3% step rate. ~+5% ≈ +100 steps ≈
   the gap.

## P2 — timeboxed architecture spikes (smoke scale, kill fast)

3. **GQA port (flag-gated).** Port `n_kv_head` from `./autoresearch/train.py:38`
   behind a flag; 300-step smoke at KV-heads ∈ {all, half, quarter}.
   Full-budget only on smoke win. Hypothesis: same quality, faster steps —
   same lever as P1.
4. **MXFP8 spike (timeboxed, compile-cost first).** Check competition legality
   of FP8 matmuls, then measure compile + first-100-step overhead before any
   quality run. Kill if compile eats >5% of budget. Quality run only if
   throughput-neutral or better.

## P3 — joint batch×LR sweep (3–4 slots, only after P0–P1)

5. **Batch × LR × warmup, full budget, EMA eval.** Grid: batch ∈ {65k, 131k,
   262k} × LR scale ∈ {0.7×, 1×, 1.4×} around current, warmup ∈ {300} fixed
   first, then perturb the winner. The 65k loss (1.0488) is one point, not a
   sweep — do not treat it as closed.

## P4 — data-pipeline variants (cheap, rules-safe)

6. **Reshuffle / repack variants.** Different document ordering, packing, and
   epoch-boundary handling. Read-only changes to the input stream; each gets
   one full-budget slot only if 300-step smoke shows a loss-curve separation.
7. **Loss weighting by token byte-length (read-only).** Weight each token's
   loss by its byte length — closer to the bpb objective than mean CE, no
   model change, no extra state. Smoke first.
8. **Checkpoint averaging (single model at eval).** Average last-k checkpoints
   (or EMA trajectory points) into one stateless model for `load_for_eval`.
   Legal if the submitted artifact is one static model. Near-zero cost.

## Kill criteria / discipline

- No architecture change without a 300-step smoke win.
- No number without its eval def label and seed.
- Cap exotic-kernel work at zero further slots (see audit §4) until P0–P4
  are exhausted.
- Stop-the-line rule: any run beating 1.004355 same-def in-budget becomes
  the new locked baseline immediately; rebase pending items onto it.
